# Метки

Карта мира с метками рядом с человеком, 3D-зданиями Польши и закрытым сайтом модерации.

- **Основной сайт:** `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`
- **Модерация:** тот же адрес + `moderation/`. Ссылок на неё с основного сайта нет.

Сайт полностью бесплатен: хостинг на GitHub Pages, а аккаунты, метки и жалобы хранит Firebase на
тарифе Spark. Банковская карта не нужна.

## Как запустить

Нужно один раз сделать шаги ниже: примерно 20 минут. Пока шаги 1-5 не сделаны, карта и GPS
уже работают, а вход показывает сообщение «Вход пока недоступен».

### 1. Создайте проект Firebase

Откройте [консоль Firebase](https://console.firebase.google.com) и создайте проект. Google Analytics
и Gemini можно выключить: они не нужны. Тариф оставьте бесплатным (**Spark**).

### 2. Включите вход

1. **Authentication → Sign-in method**: включите **Google**.
2. **Authentication → Settings → Authorized domains**: добавьте `ВАШ_ЛОГИН.github.io`.

### 3. Создайте базу и правила доступа

1. **Firestore Database → Create database**, режим **production**, регион
   **europe-central2 (Варшава)**. Регион потом не изменить.
2. Вкладка **Rules**: замените всё содержимым файла [`firestore.rules`](firestore.rules) и нажмите
   **Publish**.

Без этого шага база закрыта полностью, и сайт покажет «Не удалось открыть аккаунт».

### 4. Подключите сайт к Firebase

1. **Project settings → General → Your apps → значок `</>`** и зарегистрируйте веб-приложение.
2. Скопируйте значения в файл [`src/shared/firebase-config.ts`](src/shared/firebase-config.ts).

Эти значения не секретны: их видит браузер любого посетителя. Данные защищает `firestore.rules`.

### 5. Заполните юридические данные

В файле [`src/shared/site-config.ts`](src/shared/site-config.ts) укажите имя или название
администратора данных, адрес и почту.

Тексты согласия и политики в [`src/shared/legal.ts`](src/shared/legal.ts) это шаблон под GDPR.
**Перед запуском покажите их юристу.**

### 6. Опубликуйте на GitHub

1. Создайте публичный репозиторий на [github.com/new](https://github.com/new). Для бесплатных
   аккаунтов GitHub Pages работает только с публичными репозиториями.
2. Загрузите файлы проекта. Папки `node_modules`, `dist`, `e2e-dist` и `test-results` не нужны.
3. **Settings → Pages → Source: GitHub Actions**.
4. Откройте вкладку **Actions**: сайт соберётся и опубликуется сам за пару минут. Если первая
   сборка запустилась до шага 3, нажмите **Re-run jobs**.

Дальше каждое изменение в ветке `main` публикуется автоматически. Если проверки не прошли,
старая версия сайта остаётся на месте.

### 7. Назначьте первого модератора

1. Откройте `.../moderation/` и войдите через Google. Появится экран «Нет доступа» с кодом.
2. В консоли Firebase: **Firestore Database → Start collection**, имя `moderators`.
3. **Document ID** = этот код, добавьте любое поле, например `addedAt` со значением `1`.
4. Обновите страницу модерации.

Других модераторов назначайте так же. Убрать модератора: удалить его документ из `moderators`.

## Как это работает

| Что | Как устроено |
|---|---|
| Карта | [MapLibre](https://maplibre.org) и [OpenFreeMap](https://openfreemap.org): бесплатно, без ключа |
| 3D только в Польше | Отдельный источник зданий по точному контуру страны из OpenStreetMap |
| GPS | Высокая точность браузера. Координаты не покидают устройство |
| Вход | Firebase Auth: только Google. Телефон человек вводит сам |
| Защита | [`firestore.rules`](firestore.rules): все проверки выполняет сервер, а не сайт |

Статусы: аккаунт `pending` → `approved` / `rejected` / `banned`; метка `pending` → `approved` /
`rejected` / `removed`; жалоба `open` → `resolved` / `dismissed`.

## Что важно знать

- **Телефон не проверяется.** Коды из SMS в Firebase доступны только на платном тарифе Blaze,
  поэтому номер можно ввести любой, и модератор видит пометку «не проверен». Подтверждена только
  почта Google, поэтому блокировка закрепляется за почтой. Вход и подтверждение по SMS были в
  первой версии: чтобы вернуть их, подключите Blaze и восстановите код из коммита `a4d6b79`.
- **Проверка 800 метров выполняется на устройстве.** Браузер сообщает координаты сам, и сервер не
  может их проверить. Человек с техническими навыками может подделать GPS или прочитать тексты
  меток из данных, которые получил браузер. Это верно для любого сайта. Доступ к меткам есть только
  у одобренных пользователей, а за нарушения их можно заблокировать.
- **Здания объёмные, но без фасадов и крыш.** Это коробки с настоящей высотой из OpenStreetMap,
  как 3D-режим Google Maps в 2010-х. Фотореалистичные модели есть только у платных сервисов.
- **Метки загружаются все сразу**, до 5000 штук. Для большего числа нужна загрузка по видимой
  области карты.
- **OpenFreeMap** существует на пожертвования и не даёт гарантий. Для коммерческого проекта с
  большой нагрузкой стоит поднять свой сервер карт или взять платный.

## Для разработчика

Нужны Node.js 22+ и Java 21 (для локального Firebase).

```bash
npm install
```

```bash
npm test
```

```bash
npm run emulators
```

```bash
npm run dev:emulator
```

Основной сайт откроется на `http://127.0.0.1:5173`, модерация на `/moderation/`.

Тесты правил доступа:

```bash
npm run test:rules
```

Браузерные сценарии. Сначала соберите обе версии и запустите эмулятор:

```bash
npx vite build --mode emulator --outDir e2e-dist/metki-map
```

```bash
npx vite build --outDir e2e-dist/unconfigured
```

```bash
npm run test:e2e
```

По умолчанию используется Microsoft Edge. Другой браузер: переменная `E2E_CHANNEL=chrome`.

| Папка | Что внутри |
|---|---|
| `src/app` | Основной сайт |
| `src/moderation` | Сайт модерации |
| `src/shared` | Общий код: Firebase, геометрия, тексты документов, контур Польши |
| `tests` | Модульные тесты, тесты правил доступа, браузерные сценарии |
